Use AI Tools by Role

Choose the right tool for the job. Figma is your design source, AI is your build tool, and the browser is where you verify it actually works.

Prototype Building

Codex, Cursor, Claude

Use these when you want AI to create files, modify code, run the app, and fix visual or interaction issues.

Experience Design & Thinking

Claude, ChatGPT, Gemini

Use these to work through flows, product logic, edge cases, UX copy, research, critique, and better prompts.

Interactive 3D Design Prototyping

Spline, Omma

Spline and Omma can be used together to quickly explore 3D scenes, motion, spatial interfaces, product objects, and immersive experiences.

Core Concepts Worth Knowing

Concepts designers commonly encounter when getting AI to build working prototypes.

ViteA lightweight app starter that lets you preview React prototypes quickly in the browser.
npmA tool for installing and running packages needed for JavaScript projects. Designers typically only use a few simple commands.
npm run devThe command that starts a local preview server. It usually opens an address like http://localhost:5173.
Root folderThe top-level folder of your project. AI uses this as the reference point for files, assets, tokens, and instructions.
Design tokensColor, typography, spacing, and shadow values that AI should reuse rather than invent arbitrary ones.
SKILLS.md / SKILL.mdA short instruction file that tells AI your team's prototyping standards and quality criteria.

Getting Started with AI Prototyping

A simplified flow to get you started without needing to be an engineer.

1

Install

Use Codex or Cursor for building. You'll also need Node.js to run the prototype locally.

2

Gather Materials

Collect your Figma links, screenshots, design tokens, sample content, and product notes into a single project folder.

3

Prompt

Tell AI the goal, the Figma frames you're using, the interactions you need, and what to keep simple.

4

Run

Ask AI to run the app with npm run dev, then open the local URL in your browser.

5

Review

Click through the prototype and compare it to Figma. Check spacing, typography, color, states, and mobile layout.

6

Refine

Don't dump all feedback at once. Break it into rounds: visual accuracy first, then interactions, then polish.

04

Connecting Figma MCP

Figma MCP helps AI more accurately read design context like selected frames, components, variables, and styles.

  • Use the remote Figma MCP server when possible.
  • Add https://mcp.figma.com/mcp to your AI tool's MCP settings.
  • Connect your Figma account and grant access permissions.
  • Open your Figma file and select the frame you want to prototype.
  • Copy the link to the selected frame or layer.
  • Paste the link into an MCP-compatible tool like Codex, Cursor, or Claude Code.
  • Ask AI to analyze the design before generating any code.

The Desktop MCP runs through the Figma desktop app and is typically used in specific organizational or enterprise environments.

Recommended Root Folder Structure

The root folder is the reference point for your prototype. A clean structure helps AI understand exactly what to modify.

prototype-name/
  README.md
  package.json
  index.html
  src/
    App.jsx
    main.jsx
    styles.css
    components/
    data/
    assets/
  design/
    figma-link.md
    screenshots/
    tokens.json
  notes/
    prompts.md
    decisions.md
    SKILLS.md

src/ is where the actual prototype code lives.

components/ stores reusable UI pieces like buttons, cards, and navigation.

data/ holds sample data that makes the prototype feel realistic.

design/ stores your Figma links, screenshots, and design tokens.

notes/ stores prompts, decisions, and AI skill instructions.

Adding Spline or Omma 3D Designs

Spline and Omma are useful for explaining or interactively exploring products, objects, spaces, and motion in 3D.

  • Prepare your interactive 3D design in Spline or Omma.
  • Get a shareable embed URL or export file ready.
  • Embed it in the prototype using a viewer package, iframe, image, video, or 3D asset — whichever fits best.
  • Keep the 3D area responsive and avoid making it too heavy.
  • Don't put critical text only inside the 3D scene — also provide it in the HTML UI.
  • Prepare a static fallback image for slower devices.
Add this 3D design as the main interactive visual in the prototype.
Keep it responsive and include a fallback image.
3D design URL: [Paste Spline or Omma URL here]

SKILLS.md for More Accurate AI Output

SKILLS.md is an instruction file that tells AI how your design team works, your quality standards, and the rules for building prototypes.

What to Include

  • The user and prototype purpose
  • Design token usage rules
  • Component usage rules
  • Responsive layout standards
  • Interaction and motion standards
  • Accessibility standards
  • What AI should avoid

Where to Put It

Save it near your prototype notes — for example at notes/SKILLS.md. Some AI tools expect the singular SKILL.md, so match the filename to what your tool expects.

Simple SKILLS.md Template

# AI Prototyping Skills for Product Designers

## Role
Act as a senior product designer and frontend prototyper.

## Goal
Build accurate, clickable prototypes based on Figma designs.

## Design Rules
- Use the provided design tokens exactly as given.
- Match spacing, typography, color, radius, and component states.
- Prefer existing components before creating new ones.
- Make everything responsive for both desktop and mobile.

## Interaction Rules
- Add realistic hover, focus, selected, loading, empty, and error states.
- Keep flows simple and testable.
- Don't create new screens that aren't needed.

## Output Rules
- Keep code easy to modify.
- Use realistic sample data.
- Explain what's clickable, what's static, and what's a placeholder.
- Share your assumptions before making large changes.

## What to Avoid
- Arbitrary colors not in the tokens.
- Decorative UI not in the design.
- Overly complex structure for the scope of the prototype.

Pushing Code to GitHub

The most basic flow for saving and sharing code built through AI prototyping on GitHub.

00

What You Need to Know First

  • GitHub is a service for storing and sharing code online.
  • Repo is a project folder inside GitHub. If a Figma file is the source of truth for design, a repo is the source of truth for code.
  • Local project is the prototype folder on your computer. Example: AI Prototyping Guide
  • Terminal is the app where you type commands. On Mac use Terminal; in Cursor use the Terminal panel at the bottom.
  • Remote is the online GitHub repo address linked to your local folder.
  • Origin is a nickname for the remote. The first GitHub repo is usually called origin.
  • Main is the default branch name. Think of a branch as the main line of your work.
01

Create a GitHub Repo

Do this step in the browser on the GitHub website.

  1. Log in to GitHub.
  2. Click the + button in the top right and select New repository.
  3. Enter a repository name. Example: ai-checkout-prototype
  4. Choose visibility: Private or Public.
  5. If you already have code locally, skip adding a README, gitignore, or license — it's easier that way.
  6. Click Create repository.
  7. Copy the repo URL shown after creation. Example: https://github.com/USERNAME/REPO-NAME.git
02

Where to Type Commands

Commands must be entered from inside your prototype project folder.

  1. Open your prototype folder in Codex or Cursor.
  2. Open the terminal. In Cursor it's usually the Terminal panel at the bottom.
  3. Confirm the terminal is pointing to your project folder.
pwd

pwd shows which folder the terminal is currently looking at.

03

Connect Your Local Project to GitHub

Enter these commands one line at a time in the terminal. Replace USERNAME and REPO-NAME with your GitHub details.

git init
git add .
git commit -m "Initial AI prototype"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO-NAME.git
git remote -v

If you see the GitHub URL after running git remote -v, the connection is set up. If a remote already exists, use git remote set-url origin [new GitHub URL].

04

Push the AI Prototype Code

Push uploads your saved version from your computer to the GitHub repo. Enter this command in the terminal.

git push -u origin main

For future updates, just repeat this flow.

git status
git add .
git commit -m "Update prototype"
git push origin main
05

What Each Command Does

  • pwd shows the folder the terminal is currently open in.
  • git init turns the current folder into a Git-tracked project.
  • git status shows which files have been changed.
  • git add . stages changed files for commit.
  • git commit saves a snapshot of the current version.
  • git remote add origin ... links your local folder to the GitHub repo.
  • git push uploads the saved version to GitHub.
06

Designer Checkpoints

  • Commands go in the terminal, not on the GitHub website.
  • The terminal must be open inside your prototype project folder.
  • Never push files containing API keys, passwords, tokens, or personal data.
  • When asking Codex or Cursor, you can say: "Check the changes, commit them, and push to GitHub."

Useful Tips

Small habits that improve the quality of your AI prototypes.

  • Start with one core user journey before expanding the prototype further.
  • Pass Figma links, screenshots, tokens, and product notes together.
  • Request changes in small steps rather than asking for a full rebuild at once.
  • Use realistic sample data so you can properly evaluate the UI.
  • Save prompts that worked well in notes/prompts.md.
  • Document what's clickable, what's static, what uses fake data, what's unfinished, and what was intentionally simplified.
